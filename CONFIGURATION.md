# Configuration Reference

All configurable Terraform values are declared in `variables.tf`. Subscription, resource names, location, and common tags are required inputs; reusable service settings retain defaults.

The AzureRM and AzAPI provider version constraints remain in the Terraform `required_providers` block because Terraform does not allow input variables in provider version constraints. AzAPI manages the APIM parent service; AzureRM manages its child resources and the other Azure services.

## Override Precedence

Terraform applies variable values using its standard precedence rules. Common options are shown below.

### Variable File

Copy the example and edit the copy:

```powershell
Copy-Item terraform.tfvars.example terraform.tfvars
terraform plan
terraform apply
```

`terraform.tfvars` and other `*.tfvars` files are ignored by Git in this repository.

Use a specifically named file when managing multiple environments:

```powershell
terraform plan -var-file="environments/dev.tfvars"
terraform apply -var-file="environments/dev.tfvars"
```

Ensure environment variable files remain outside source control when they contain sensitive or private values.

The command-line and environment-variable examples below assume all other required values are supplied by an auto-loaded file such as `terraform.tfvars` or by another supported input source.

### Command-Line Value

Override one value for a command:

```powershell
terraform plan `
  -var="resource_group_name=rg-eventgrid-dev" `
  -var="location=westeurope"
```

### Environment Variable

Terraform reads variables prefixed with `TF_VAR_`:

```powershell
$env:TF_VAR_azure_subscription_id = "<azure-subscription-id>"
$env:TF_VAR_apim_name = "my-unique-apim-name"
terraform plan
```

Remove values after use:

```powershell
Remove-Item Env:TF_VAR_azure_subscription_id
Remove-Item Env:TF_VAR_apim_name
```

## Variable Reference

### Azure Deployment

| Variable | Default / requirement | Purpose |
|---|---|---|
| `azure_subscription_id` | Required | Target Azure subscription |
| `resource_group_name` | Required | Resource group name |
| `location` | Required | Azure region |
| `common_tags` | Required | Tags applied to supported resources |

### Managed Identity and Storage

| Variable | Default / requirement | Purpose |
|---|---|---|
| `managed_identity_name` | `apim-mi` | User-assigned identity used by APIM |
| `storage_account_name` | Required | Storage account containing tenant queues |
| `storage_account_tier` | `Standard` | Storage performance tier |
| `storage_replication_type` | `LRS` | Storage replication mode |
| `storage_shared_access_key_enabled` | `true` | Enables shared-key access used by the test runner |

Storage account, APIM, and Event Grid domain names must be globally unique and must be provided for each environment.

The Storage Account is reachable through its public network endpoint, but anonymous public access for nested resources is disabled. Clients must still authenticate and be authorized. Shared-key access is enabled for the included queue-delivery tests, which retrieve the Storage Account key at runtime. For production, review this setting and prefer Microsoft Entra authorization where possible.

### Event Grid and Policy

| Variable | Default / requirement | Purpose |
|---|---|---|
| `eventgrid_domain_name` | Required | Event Grid domain name |
| `eventgrid_sender_role_name` | `EventGrid Data Sender` | Role granted to the APIM managed identity |
| `eventgrid_request_timeout_seconds` | `30` | APIM outbound request timeout |
| `eventgrid_token_audience` | `https://eventgrid.azure.net/` | Managed identity token audience |
| `event_type` | `tenant.event` | Event Grid event type generated by APIM |
| `event_data_version` | `1.0` | Event Grid data version generated by APIM |

Changing the role name or token audience can break APIM-to-Event-Grid authentication. Override these only for a deliberate architecture change.

### API Management

| Variable | Default / requirement | Purpose |
|---|---|---|
| `apim_name` | Required | APIM service name |
| `apim_publisher_name` | `Publisher` | Publisher display name |
| `apim_publisher_email` | `publisher@example.com` | Publisher contact email; replace for a real deployment |
| `apim_sku_name` | `Standard_1` | APIM SKU and capacity |
| `api_name` | `events-api` | Internal API identifier |
| `api_revision` | `1` | API revision |
| `api_display_name` | `Events API` | Portal display name |
| `api_path` | `events` | Public API path prefix |
| `api_protocols` | `["https"]` | Exposed protocols |
| `api_subscription_required` | `true` | Requires APIM subscription authentication |
| `api_operation_id` | `publish-event` | Publish operation identifier |
| `api_operation_display_name` | `Publish Event` | Publish operation display name |
| `api_operation_method` | `POST` | Publish HTTP method |
| `api_operation_url_template` | `/{tenantId}` | Publish operation route |
| `tenant_parameter_name` | `tenantId` | Route parameter read by the APIM policy |
| `tenant_parameter_description` | Current tenant routing description | Portal description |

Keep `api_operation_url_template` and `tenant_parameter_name` consistent. For example, if the parameter becomes `customerId`, use both `/{customerId}` and `customerId`.

Do not set `api_subscription_required = false` unless another authentication policy, such as Microsoft Entra ID `validate-jwt`, has already been deployed and tested.

## Tenant Map

The current `tenantA`, `tenantB`, and `tenantC` keys are demonstration tenant IDs. They are not Terraform attributes or reserved names. Each map key is simultaneously:

- the logical tenant ID;
- the APIM subscription ID;
- the Event Grid domain topic name;
- the value accepted in the API route.

The map key must therefore match the identifier assigned to that client's APIM subscription and used in `/events/<tenant-id>`. The policy compares the route value and APIM subscription ID case-sensitively, so callers must preserve the configured spelling and capitalization.

| Value | Required naming rules | Uniqueness |
|---|---|---|
| Tenant map key | 3-50 characters; start with a letter; end with a letter or number; only letters, numbers, and hyphens | Unique in `var.tenants`; also becomes a topic name and APIM subscription ID |
| `queue_name` | 3-63 characters; only lowercase letters, numbers, and hyphens; start and end with a letter or number; no consecutive hyphens | Unique within the Storage Account |
| `event_subscription_name` | When provided, 3-64 characters; only letters, numbers, and hyphens | Scoped to the Event Grid topic |

`queue_name` is the internal Azure Storage Queue that receives events for the tenant. It does not authenticate the client and does not have to equal the tenant ID. Use a convention that makes ownership clear, such as `contoso-events` for tenant `contoso`.

`event_subscription_name` is optional. When omitted, Terraform uses `<tenant-id>-sub`.

Overriding a map replaces the complete default map; include every tenant that must remain managed.

Treat the map key and queue name as stable. Renaming a map key replaces the tenant-scoped resources and changes the public route and APIM subscription. Renaming `queue_name` replaces the queue, so migrate or drain existing messages first.

## PowerShell Integration

After `terraform apply`, `outputs.tf` stores a non-secret `deployment_config` output. The test runner loads it through `terraform-config.ps1`:

```powershell
$config = Get-TerraformDeploymentConfig
```

The helper does not add configuration of its own. It:

- runs Terraform against the repository directory through `-chdir`, regardless of the caller's current directory;
- reports a clear error when the output cannot be read;
- parses and validates the JSON before returning a PowerShell object.

This keeps resource names, endpoints, API paths, event settings, and tenant queue mappings synchronized with Terraform overrides without duplicating those values in scripts.

Inspect the output manually:

```powershell
terraform output -json deployment_config
```

The output intentionally excludes APIM subscription keys and other secrets. The test runner retrieves a selected tenant key from Azure only at runtime.

If the output is missing, run:

```powershell
terraform apply
```

The runner requires an applied state because computed values such as the APIM gateway URL and Event Grid endpoint do not exist before deployment.

## Example: Deploy a Development Environment

Create `dev.tfvars`:

```hcl
azure_subscription_id = "<development-subscription-id>"
resource_group_name    = "rg-eventgrid-dev"
location               = "westeurope"
storage_account_name   = "myeventgriddev001"
eventgrid_domain_name  = "my-eventgrid-dev"
apim_name               = "my-eventgrid-apim-dev"
apim_publisher_name     = "Platform Team"
apim_publisher_email    = "platform@example.com"
apim_sku_name           = "Developer_1"

common_tags = {
  Environment = "development"
}

tenants = {
  tenantDev = {
    queue_name = "tenant-dev-events"
  }
}
```

Deploy it explicitly:

```powershell
terraform plan -var-file="dev.tfvars"
terraform apply -var-file="dev.tfvars"
.\test-solution.ps1 -TenantId tenantDev
```

The apply operation provisions the APIM API policy together with the other Azure resources; no post-deployment policy script is required.

Use a remote Terraform backend for shared or production environments. Never commit local state files.
